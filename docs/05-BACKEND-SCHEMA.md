# Backend Schema: Tendril

> **I'm building:** An open-source AI coding harness for Termux: one headless agent daemon, a CLI client, and a WebView-based UI, all connected to the same live sessions.
> **Audience:** Android developers who code on their phone in Termux, and open-source contributors.

Storage is a single local SQLite file (`~/.tendril/tendril.db`, WAL mode) opened through Node's built-in `node:sqlite`. There is **no `users` table**: Tendril is a single-user, single-device tool, and the device owner is the only principal. Identity exists only to tell the CLI and paired web clients apart (`web_clients`). Credentials and settings live in small JSON files next to the database (documented at the end).

Conventions: ids are 26-character time-sortable strings generated by the app (timestamp prefix + random); timestamps are ISO-8601 UTC text (`2026-11-09T12:34:56.789Z`); JSON columns hold UTF-8 JSON text; every connection runs `PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000;`. The daemon is the only process that opens the database.

## Authentication flow

Everything is local; there is no signup and no password.

1. **Sign up:** none. The first daemon start creates `~/.tendril/` (mode 0700), `state.json`, and the database.
2. **CLI login:** every daemon start generates a fresh random `cliToken` (32 bytes, base64url) and writes it to `~/.tendril/state.json` (mode 0600). The CLI reads that file and sends `Authorization: Bearer <cliToken>`. File permissions are the credential boundary: any process running as the Termux user can read it, and that is accepted by design (same trust level as the user's shell).
3. **Web login (pairing):**
   1. Bearer-authenticated `POST /api/pair/code` creates a one-time code (8 characters from Crockford base32, 40 bits) held in memory with a 5-minute expiry. It is never written to disk.
   2. The browser or WebView opens `/pair#code=XXXXXXXX` (fragment, so the code is not sent in an HTTP request line or logged).
   3. The page calls `POST /api/pair {code, label}`. On a valid unused code the daemon deletes the code, creates a random 32-byte client token, stores `sha256(token)` in `web_clients`, and sets `Set-Cookie: tdl_session=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=31536000`.
   4. Invalid code attempts are counted in memory; 5 failures in 60 s lock the endpoint for 60 s.
4. **Session / token:** each web request carries the cookie; the daemon hashes it, looks up `web_clients` where `revoked_at IS NULL`, and updates `last_seen_at` (at most once per minute per client). The cookie is valid until revoked, so restarts do not log anyone out. SSE connections are re-validated every 30 s and closed if the client was revoked.
5. **Logout and revoke:** `POST /api/logout` or Settings > Clients > Revoke sets `revoked_at` and closes that client's streams. `tendril stop` removes `state.json`; the next start issues a new `cliToken`, which invalidates any CLI instances that cached the old one. Password reset does not exist; recovery from a lost paired device is "revoke it" and pairing again.
6. **Provider credentials:** stored in `~/.tendril/auth.json` (0600), never in SQLite, never returned by the API except as a masked suffix.

## Relationships

- sessions 1 → many messages (`messages.session_id`, cascade delete)
- sessions 1 → many tool_runs (`tool_runs.session_id`, cascade delete)
- messages 1 → many tool_runs (`tool_runs.message_id`, cascade delete); one assistant message may request several tools
- tool_runs 1 → 0..1 snapshots (`snapshots.tool_run_id`, unique; only `write_file` and `edit_file` produce snapshots)
- sessions 1 → many snapshots (`snapshots.session_id`, cascade delete)
- permission_rules and sessions are related only by `workspace_path` value (no foreign key; rules outlive sessions on purpose)
- web_clients is independent (no relation to sessions: any paired client can open any session)
- Feature mapping: F8 → sessions, messages; F6/F7 → tool_runs; F10 → snapshots; F7 → permission_rules; F4 → web_clients; F1 → schema_migrations; F11 → `sessions.summary*`, `context_tokens`.

## Access rules

- **Single principal:** the only process that touches the database is the daemon. The file and directory are `0600` / `0700`; sibling Termux apps cannot read them (Android app sandbox), and other Android apps can reach the daemon only over `127.0.0.1` HTTP, which requires the Bearer token or a paired cookie.
- **sessions, messages, tool_runs, snapshots:** readable and writable only through authenticated API routes (Bearer or valid cookie). Any authenticated client may read any session (single-user device); no per-session ACL in v1.
- **File-access scoping:** the Files and Diff routes and every agent file tool resolve paths against the session's `workspace_path`, `realpath`, and reject anything outside it (including symlink escapes). The directory chooser (`/api/fs/dirs`) is limited to `$HOME` and the `realpath` of `~/storage/shared` when present.
- **permission_rules:** created only by an explicit "Allow always" answer from an authenticated client; deletable from Settings > Permissions or `/rules`; the agent can never create, edit, or read rules.
- **web_clients:** a web client can list and revoke clients (including itself); the stored value is only a hash; the raw cookie token is never retrievable. Pairing codes are in-memory only.
- **Secrets:** provider API keys are write-only through the API (`PUT /api/providers/:id` accepts a key; `GET` returns `"••••" + last4`). Keys and cookie values are redacted in logs and removed from the environment of `bash` subprocesses.
- **Retention:** nothing expires automatically. Deleting a session cascades to its messages, tool runs, and snapshots. `VACUUM` runs on `tendril doctor --repair`, never implicitly.
- **Backups:** `~/.tendril/` is the whole state; copying the folder (with the daemon stopped) is a complete backup. The daemon never uploads it anywhere.

## Initial migration (migration 1)

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL
);

CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL DEFAULT 'New session',
  workspace_path TEXT NOT NULL,
  provider_id TEXT NOT NULL,
  model TEXT NOT NULL,
  mode TEXT NOT NULL DEFAULT 'ask' CHECK (mode IN ('plan','ask','auto-edit','yolo')),
  status TEXT NOT NULL DEFAULT 'idle' CHECK (status IN ('idle','running','awaiting_permission','interrupted','error')),
  summary TEXT,
  summary_upto_seq INTEGER,
  input_tokens INTEGER NOT NULL DEFAULT 0,
  output_tokens INTEGER NOT NULL DEFAULT 0,
  context_tokens INTEGER NOT NULL DEFAULT 0,
  next_event_seq INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_sessions_workspace ON sessions(workspace_path, updated_at DESC);
CREATE INDEX idx_sessions_updated ON sessions(updated_at DESC);

CREATE TABLE messages (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('user','assistant')),
  content_json TEXT NOT NULL,
  origin TEXT NOT NULL DEFAULT 'cli' CHECK (origin IN ('cli','web','system')),
  stop_reason TEXT,
  input_tokens INTEGER,
  output_tokens INTEGER,
  created_at TEXT NOT NULL,
  UNIQUE (session_id, seq)
);

CREATE TABLE tool_runs (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  message_id TEXT NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
  tool_use_id TEXT NOT NULL,
  name TEXT NOT NULL,
  class TEXT NOT NULL CHECK (class IN ('read','edit','exec','net','system')),
  input_json TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('pending','awaiting_permission','running','ok','error','denied','aborted')),
  decision TEXT CHECK (decision IN ('allow_once','allow_always','deny','auto_mode','auto_rule','blocked_guard','blocked_path')),
  decided_by TEXT,
  decision_note TEXT,
  result_preview TEXT,
  exit_code INTEGER,
  duration_ms INTEGER,
  created_at TEXT NOT NULL,
  finished_at TEXT
);
CREATE INDEX idx_tool_runs_session ON tool_runs(session_id, created_at);

CREATE TABLE snapshots (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  tool_run_id TEXT NOT NULL UNIQUE REFERENCES tool_runs(id) ON DELETE CASCADE,
  path TEXT NOT NULL,
  existed_before INTEGER NOT NULL CHECK (existed_before IN (0,1)),
  content_before BLOB,
  sha256_before TEXT,
  sha256_after TEXT NOT NULL,
  diff_unified TEXT NOT NULL,
  added_lines INTEGER NOT NULL,
  removed_lines INTEGER NOT NULL,
  skipped_reason TEXT CHECK (skipped_reason IN ('too_large','binary')),
  undone_at TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_snapshots_session ON snapshots(session_id, created_at DESC);

CREATE TABLE permission_rules (
  id TEXT PRIMARY KEY,
  workspace_path TEXT NOT NULL,
  tool TEXT NOT NULL,
  pattern TEXT NOT NULL,
  decision TEXT NOT NULL DEFAULT 'allow' CHECK (decision IN ('allow','deny')),
  created_at TEXT NOT NULL,
  UNIQUE (workspace_path, tool, pattern)
);

CREATE TABLE web_clients (
  id TEXT PRIMARY KEY,
  token_hash TEXT NOT NULL UNIQUE,
  label TEXT NOT NULL,
  user_agent TEXT,
  created_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL,
  revoked_at TEXT
);

INSERT INTO schema_migrations (version, applied_at) VALUES (1, strftime('%Y-%m-%dT%H:%M:%fZ','now'));
```

## Non-database files

**`~/.tendril/state.json`** (0600, runtime, deleted on clean stop)
```json
{ "pid": 12345, "port": 7421, "cliToken": "base64url…", "version": "0.1.0", "startedAt": "2026-11-09T12:00:00.000Z" }
```

**`~/.tendril/auth.json`** (0600)
```json
{
  "providers": {
    "anthropic": { "type": "anthropic", "name": "Anthropic", "apiKey": "…", "baseUrl": null },
    "openrouter": { "type": "openai-compatible", "name": "OpenRouter", "apiKey": "…", "baseUrl": "https://openrouter.ai/api/v1" }
  }
}
```

**`~/.tendril/config.json`**
```json
{
  "port": 7421,
  "defaultProvider": "anthropic",
  "defaultModel": "claude-sonnet-5-5",
  "defaultMode": "ask",
  "maxStepsPerTurn": 50,
  "maxConcurrentTurns": 3,
  "wakeLock": true,
  "additionalDirs": [],
  "models": { "anthropic/claude-sonnet-5-5": { "contextWindow": 200000 } }
}
```
`defaultMode` accepts `plan`, `ask`, `auto-edit` only; `yolo` is rejected here by design. Model ids and context windows are user-entered values, not shipped defaults, so they cannot go stale in the code.
